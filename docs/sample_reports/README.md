# 报告质量实证样本

本目录存档多 Agent 报告生成系统的**真实运行输出**，用于验证输出质量、演示自纠错回路，作为面试时"如何保证生成质量"的实证。

## 已存档样本

| 样本 | 类型 | 篇幅 | 审核过程 |
|------|------|------|----------|
| `DeepSeek与ChatGPT的对比` | 对比型 | 4314 字节 | 3 轮 minor_issues → 兜底生成 |
| `2026年中国大模型商业化落地趋势` | 单主题型 | 8315 字节 | 3 轮 minor_issues → 兜底生成 |

## 质量评估框架（5 维度）

1. **篇幅与章节充实度** — 是否完整，而非空壳骨架
2. **对比/分析结构** — 对比型是否有"分别说明+对比总结"，单主题型是否分层
3. **来源标注** — 关键断言是否带 `据XXX报道` / `source_N`
4. **置信度表述** — 高置信直接陈述，低置信用"有观点认为"
5. **矛盾处理** — 是否有"矛盾观点"章节，且给出裁决理由

## 实测结论

- **输出质量过关**：两份报告均达到上述标准，非空壳。
- **自纠错回路真实工作**：两份报告的日志都显示审核 Agent 连续 3 次返回 `minor_issues`，每次触发撰写节点重写，3 轮后达 `MAX_ITERATIONS` 兜底生成。这是多 Agent 自纠错的实证。
- **已知调优空间**：连续 3 轮均为 `minor_issues`，说明"审核指出问题 → 撰写修好问题"的循环效率有限，存在撰写节点执行力 gap。这是调优方向，不是缺陷。
